Висновки
Сортування вставками має середню та найгіршу часову складність:

𝑂(𝑛2)

O(n2)
Тому зі збільшенням розміру масиву його час виконання суттєво зростає, особливо на випадкових даних і даних у зворотному порядку. Водночас для вже відсортованих або майже відсортованих масивів цей алгоритм може працювати швидко.

Сортування злиттям має стабільну часову складність:

𝑂
(𝑛 log ⁡ 𝑛)

O(nlogn)
Воно значно ефективніше за сортування вставками на великих наборах випадкових даних. Проте власна реалізація на Python має додаткові витрати на рекурсивні виклики, створення підсписків і злиття списків.

Timsort поєднує переваги сортування злиттям і сортування вставками. Він використовує природні впорядковані фрагменти даних, а для коротких фрагментів застосовує сортування вставками. Завдяки цьому Timsort особливо ефективний для реальних даних, які часто вже частково відсортовані.

За результатами вимірювань Timsort зазвичай показує найкращий час виконання. Саме тому в практичній розробці доцільно використовувати вбудовані функції Python sorted() або метод списку .sort(), а не реалізовувати алгоритми сортування вручну.
