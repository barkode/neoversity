Висновки з результатів тестування

1. Timsort — беззаперечний лідер sorted () та .sort () показують найкращий час у всіх сценаріях — на порядки швидше за
   інші алгоритми. На масиві 10 000 елементів Timsort у ~14 000 разів швидший за Insertion Sort на випадкових даних.

2. Insertion Sort — катастрофа на великих даних

   | Розмір | Випадкові  | Зворотній порядок |
            |--------|------------|-------------------|
   | 100    | 0.000095 с | 0.000200 с        |
   | 1000   | 0.011084 с | 0.021243 с        |
   | 10000  | 1.097068 с | 2.133831 с        |

   Час зростає квадратично — збільшення масиву в 10 разів → час зростає в ~100 разів. Це класичний прояв складності O
   (n²). Єдиний виняток — вже відсортовані дані: тут Insertion Sort дуже швидкий (O (n)), бо внутрішній while майже не
   виконується.

3. Merge Sort — стабільний, але повільніший за Timsort Складність O (n log n) підтверджується: збільшення масиву в 10
   разів → час зростає приблизно в 10–12 разів. Але власна реалізація на Python має накладні витрати на рекурсію та
   створення підсписків, тому програє вбудованому Timsort у 10–25 разів.

4. Bucket Sort — хороший середній варіант Значно швидший за Merge Sort і Insertion Sort, але повільніший за Timsort.
   Ефективний для рівномірно розподілених даних. На відсортованих і зворотних даних показує стабільний час, бо розподіл
   по відрах залишається рівномірним.

5. Radix Sort — передбачуваний, але не найшвидший Складність O (n·d) де d — кількість цифр. Стабільно повільніший за
   Bucket Sort приблизно вдвічі, бо виконує кілька проходів по масиву (по одному на кожен розряд). Не залежить від
   порядку даних.

6. Вплив початкового порядку даних

   | Алгоритм       | Відсортовані     | Випадкові    | Зворотній      |
      |----------------|------------------|--------------|----------------|
   | Insertion Sort | ✅ найкращий     | ❌ повільний | ❌❌ найгірший |
   | Merge Sort     | ✅ трохи швидший | нейтральний  | нейтральний    |
   | Timsort        | ✅✅ найкращий   | ✅ відмінний | ✅ відмінний   |
   | Bucket / Radix | нейтральний      | нейтральний  | нейтральний    |

   Timsort спеціально оптимізований для частково відсортованих даних — він виявляє вже впорядковані фрагменти (runs) і
   не сортує їх повторно.

Загальний висновок Використовуйте sorted () або .sort () у Python завжди, коли це можливо. Власні реалізації алгоритмів
сортування поступаються вбудованому Timsort у десятки і сотні разів — не через помилки в коді, а через те, що Timsort
реалізований у C, оптимізований роками та враховує особливості реальних даних. Написання власного алгоритму сортування
для продакшн-коду є антипатерном.ірювань Timsort зазвичай показує найкращий час виконання. Саме тому в практичній
розробці доцільно використовувати вбудовані функції Python sorted () або метод списку .sort (), а не реалізовувати
алгоритми сортування вручну.
